# KLayout technology notes

- GDS Layer Numbers: Physical layer numbers and datatypes (e.g., `"M1": {"number": 15, "datatype": 0}`)
- Layer Connectivity: Stack ordering relationships (`"previous": "CO", "next": "VIA1"`)
- Material Classifications: Layer material types (`"metal"`, `"poly"`, `"diffusion"`, `"cut"`, `"implant"`, `"marker"`)
- Pin Layer Mappings: Associated pin/label layer datatypes for electrical connectivity
- Display Properties: Layer colors and fill patterns for visualization in KLayout
- Minimum Widths: Layer-specific minimum feature sizes
- Spacings: Minimum separation between features on same layer
- Enclosure Rules: Via enclosure and opposite-side clearance requirements
- Via Specifications: Via sizes, spacings, and placement rules for each via level
- Gate Rules: Minimum gate lengths, finger spacing, and poly extension requirements
- Routing Grid: Horizontal and vertical grid alignment requirements
- Cell Spacing: Standard cell height and digital placement constraints
- Capacitor Rules: Special width and spacing requirements for precision capacitors
- Implant Rules: Well and threshold voltage layer enclosure requirements
- Available Devices: Supported device types (`"nch"`, `"pch"`, `"mres"`, etc.)
- Port Mappings: Device terminal names and order (`["d","g","s","b"]`)
- Parameter Mapping: Translation between layout parameters and schematic properties
- Device Inheritance: Base device definitions that can be specialized
- PDK Library Name: Technology library identifier for device models
- Process Node: Technology node specifications and gamma correction factors
- Property Mapping: Parameter name translations between tools
- Layer properties are saved in a .lyp file. It can be produced using a Cadence .tf, display.df, and .layermap file
  - .lyp is a XML file, essentially
  - The code is in [KLayout's `tf_import` repository](https://github.com/klayoutmatthias/tf_import)
- Once shape (rects, polygons, paths, labels) are written to a cell, the database unit is multiplied if they are the integer (non D-) types
- Layers are attached to the ly = db.Layout() object via `layer1 = ly.layer(1, 2, "Poly")`
- You can get info of a layer with `ly.get_info(layer1)`
- Layouts contain a layers list, and a shapes list for each layer
- Each shapes list contains the geometries (boxes, polygons, paths, and labels) which are on that layer
- Can I define a cell, but not place instances of it?
  - I don't think so. What happens is that when you first declare a geometric object, it doesn't belong to a cell, and so nothing exists in the layout
  - But once you create a layout and create a cells, and insert the geometry to the shape list of the cells, it now exists in the layout.
  - However, if you now declare a higher level cell, and instance the original cell twice within it, when you go to open the layout, it will show the top level hierarchy cells, and the two instance of it
- Concepts like pins and named instances are not part of the GDS and OASIS specification and that still is the basis of the program. It's possible to emulate those features (and others like net information) with user properties, but the interpretation of those is strongly dependent on the tools reading these files.

## Extraction: KLayout-PEX and FasterCap

A layout extracted by its own net names (`flow.layout.signoff.run_layout_pex`: the MOM test structures, the ADC arrays) goes to FasterCap through KLayout-PEX (`flow/layout/kpex.py`) by default; `Extractor.CALIBRE` asks for the kit's own extractor instead (Calibre's xACT, or Quantus in LF150), which stays the manual check of it.

- The stack: each PDK's `pdk/<pdk>/kpex/stack.json` (private), its conductors' heights and thicknesses and the planar dielectrics of its kit's typical interconnect corner, read from the kit's ICT file (`python -m flow.layout.kpex stack <ict> PO=poly M1=metal1 ...`; a conductor without a height sits in the dielectric before it, its top at theirs). The layers, vias and pin labels are the PDK's layout tech's (`LAYERS`, `RULES`, `PIN_TEXT`).
- The model: kpex holds one dielectric between two metals, so each metal level gets its own as a film around the metal filling the level (the slabs' mean by thickness: the field between neighbours runs along them) and the via level above it another (the slabs in series: the field between levels crosses them).
- The run: kpex's own Python (`KPEX_HOME`, `-P` so that this folder's `kpex.py` does not shadow its protobuf package) runs `kpex_extract.py`: KLayout joins the conductors through the vias and names the nets by the labels, kpex builds FasterCap's model, FasterCap (`FASTERCAP`) solves it at a tolerance of 0.005 and a mesh refinement of 0.1, Galerkin's scheme. FasterCap's Maxwell matrix leaves each net's capacitance to infinity in its row sum: that goes to ground, as an extractor whose substrate is an infinite plane counts it.
- The netlist: Spectre capacitors between the nets by their labels, ground `0`, as the kits' extractors write theirs, so `flow.layout.devices.momcap.characterize.pair_capacitances` reads either.
- The 2.5-D engine (`Engine.RCX25`): kpex's own rule-based extractor (each pair of shapes' overlap, sidewall and fringe) by the kit's coefficients, `pdk/<pdk>/kpex/parasitics.json` (private, kpex's `process_parasitics`: fitted to field solves of test structures in the kit's own stack, no foundry numbers; TSMC65's to FasterCap's 3-D solves, every other kit's by `python -m flow.layout.kpex_coefficients <pdk>`: direct 2-D solves of cross-sections, then each MOM metal's sidewall scaled to FasterCap's 3-D coupling per finger length of the capacitive DAC's strips as the kit's arrays draw them, the table's `provenance` holding every strip by both engines), in place of FasterCap for a block it does not converge on. The kit names it per block in Python (`pdk.<pdk>.signoff.engine(block)`, read by `flow.layout.signoff.engine`), not a flag; a kit without the coefficients refuses it. Every kit names it for capdac (2026-11-18), whose arrays FasterCap took 4 to 14 h on, or never finished; the 2.5-D engine takes under a minute where the capacitors stand beside the rows, 17 to 45 min where they stack over them (TSMC65, TSMC28). The pex step's output names the engine (`engine`, `extractor`), and the postsim record's annotation the extractor.
- Its sidewall stops at the edge's own polygon (2026-11-20, `flow.layout.kpex_extract._shielded_by_own_polygon`, a wrapper of kpex's visitor): kpex 0.6.12 takes, for each stretch of an edge, the nearest polygon of another net on its layer however far, past the edge's own polygon where that lies nearer. A MOM array's top plate is one merged comb, so its ring walls where a unit holds no finger (a shorter stage's ring above its fingers) saw a longer stage's finger through every wall between them, up to the halo: GF180 capdac frida1's stage 2 plate read 10 % above its neighbours'. On capdac frida1's layouts (20261119_021607), the stages' weights by the extraction alone (main less difference plate to the top plate, against the design at the fitted gain) come within 1.4 LSB in GF180 where they were 52 off, 0.4 in TPSC65 (5.2), 0.5 in SKY130 (3.3), 0.3 in TSMC65 (0.4), the other kits as they were. `flow/layout/test_kpex.py` checks the wrapper where kpex's Python is installed.
- The MOM calibration (2026-11-20, `kpex_coefficients.calibrate`): a lone pair of wires, the 2-D fit's sidewall, is not a MOM strip, whose plates stack on two or three metals at their minimum space with their own net above and below each finger. The strips, on each metal count the kit's arrays draw, the main finger at 4, 12 and 24 µm and the difference finger at its shortest, apart on both sides (and at 12 µm joined, and apart on one side and at the array's edge on the other, the array's last piece), go to FasterCap at the units' tolerance (drawn and DRC-checked as the momcap table's are, `characterize.extract`) and to the 2.5-D engine with its capacitances by coefficient (`kpex_extract.parts`). Each metal count's slope, a plate's coupling over its finger's length, sets its metals' sidewall scale, the fewest metals first; then the line ends. kpex's sidewall ends with the edge, where FasterCap's field wraps round a finger's tip: `kpex_extract.line_ends` continues each side of a line end (an edge shorter than both its neighbours, both corners convex) that many µm past the tip, by the conductor's sidewall coefficients, to the polygon it faces there; its reach per metal is fitted to the strips' plates, main finger and difference stub, their errors relative to FasterCap least squares. A strip's weight, main less difference finger, is the same whatever the reach (each finger has one tip at the ring's bar and one at their gap); the plates' own values, and the array's gain, are what it brings to FasterCap's. The table holds the reach (`line_ends_um`, frida's key, `kpex.FRIDA_KEYS`, kept out of kpex's technology with the provenance). On the strips (2026-11-20, GF180, IHP130, LF150, Tower180, SKY130; TPSC65 and TSMC28 to follow) the 2-D fit read a finger's coupling per length 2.5 to 12 % above FasterCap's (GF180 12 %, SKY130 12 %, LF150 8 % on one metal and 5 % on three, Tower180 10 % and 3.5 %, IHP130 2.5 %) and a main finger's ends 0.07 to 0.26 fF below; after it every strip's plates come within 1.7 % of FasterCap's (a difference stub at the array's edge within 3.7 %), the sidewall scales 0.89 to 0.99 and the line ends' reach 0.15 to 0.35 µm. On capdac frida1's arrays (FasterCap at 1 %): LF150's stages 4 to 15 and the edge within 1 % but for three plates (to 4.5 %, a 1 fF stub), GF180's large plates within 2 %. Two contexts the strips leave out: a ring longer than its fingers (GF180's and TPSC65's shorter stages) reads 4 % above in FasterCap, main and difference finger alike, which the 2.5-D engine does not see (a weight 0.3 LSB, the gain the rest); and at the array's edge, where the shield's frame closes through the channel, GF180's strip reads 1.7 % below an apart one in FasterCap and 0.3 % below in the 2.5-D engine.
- Post-layout simulation simulates the extraction (2026-11-20, `flow.sweep.runner._add_capacitors`): it adds the extraction's capacitors less the DUT's own drawn ones between the same nets, and where the extraction reads less than the drawn, lowers those to it (it had kept them, so a difference plate the 2.5-D engine read below its drawn value simulated as drawn beside a main plate simulated as extracted: GF180's weights moved twice as far post-layout as the extraction's). The postsim record holds what it lowered (`lowered_f`). What it lowers is mostly the top plate's capacitance to ground (2026-11-20, capdac frida1): the momcap table gives each strip the top plate's ground of a strip drawn alone (FasterCap, its sides and top open), which every strip of the array then carries, where in the array the strips abut, top plate beside top plate. The drawn against the extracted: SKY130 251 and 84 fF, IHP130 198 and 62 fF, GF180 58 and 54 fF (its whole array by FasterCap at 1 %: 36 fF, the 2.5-D engine some 40 % above it); the private kits alike. A pure attenuation: the stages' weights and the step error, fitted at the gain, are what they were; the gain and the full scale take it (pre-layout and post-layout 0.52 and 0.72 in SKY130, 0.74 and 0.86 in IHP130, 0.50 and 0.50 in GF180), the drivers' loads a few percent (each plate in series with the rest of the top plate). The table keeps it: an abutted strip's ground would take each kit's strips extracted between neighbours.
- What the extraction leaves of capdac's weight errors is the layout's (2026-11-20, capdac frida1, the 2.5-D engine as calibrated; a stage's weight, its main plate's coupling to the top plate less its difference plate's, against the drawn weights at their fitted gain, in LSB): the plates' routes beside the top plate's ring and under its landing. Where the capacitors stand beside the rows, the side is routed no higher than the metal over their shield (`flow.capdac.subckt._place`, ALIGN's `Route(max_layer)`, global: its router takes one set of metals for every net), the shield's frame a track past the ring's bars at the array's top and bottom (`MomUnit._channels`) and each band's rows far enough from the array for the routes that run along its end past one place, less three over each of the band's rows (`_crossings`, `_landing_gap_nm`, `_ROUTES_OVER_ROW`, fitted to these layouts; Tower180's difference band, eight routes past one place over its one row, had two routed under the array on M1 with fewer tracks, now none, its outline a row taller); a kit whose router cannot route so says it (`MOM_PLATES_ROUTED_LOW = False` in its layout tech: SKY130 and TPSC65, whose plate nets the limited route leaves open) and routes at any height without the frame's track. The top plate's landing at the top's inner end is shielded (`EdgePin.shield`, `flow.layout.pins`): on the highest landing metal whose metal under the wire no other signal takes, with a strip of the block's ground on that metal under the wire, as far past its sides as the wire stands over the highest metal another signal's route takes beneath it (the kit's `kpex/stack.json`), tied down to the ground's wiring by a stack of cuts and recorded beside the pin (`shield` in the layout step's pins record). In GF180 the unshielded landing, over the last two stages' difference plates' routes, put those stages 4.0 and 5.9 LSB off (0.11 fF on a 0.019 fF LSB); shielded, both within 0.2 LSB. The tie's pads, as every landing's, keep the kit's line-end rule where it gives one (its `end_of_line` in `RULES`, `pins.Kit.ends`: a line end's space in front of it, both ways, `_Space.fits`) and join the ground's own metal across any gap narrower than its space (`pins._joined`): TSMC28's tie first stood an M2 pad beside another net's M2 line end closer than that rule, then, moved, 45 nm from the ground's own M2. Left as it is: SKY130's one difference plate's route on the ring's top metal above its bar (2.8 LSB).
- capdac's sensed plates (2026-11-20, the owner's: `dac_plate`, a self-timed converter's sign that a stage has switched): each stage's main plate drives the least inverter the kit draws (`flow.layout.devices.mosfet.netlist.least_inverter`), its output the side's `dac_plate` port, the plate's complement at full swing (GF180's swing 0 to 3.3 V, against its plate's), which the ADC names `dac_plate_p` and `dac_plate_n`. The sense inverters stand in a row of their own at the main band's outer edge, each output landed on the side's bottom edge (`EdgePin(dac_plate, Border.BOTTOM)`, a pin a bit) on the lowest landing metal; where the capacitors stack over the rows the row is under them, the outline as it was, and the pins stay as laid out, as the states' do. Each sense inverter beside its driver instead widened the band's rows past their ends' ties and kept the upper rows' pins from the edge. Where the capacitors stand beside the rows the row costs its height: GF180's side 16 % larger (a 6.3 um row, and the row's 38.4 um past the side's 36.9 um width), IHP130's 13 % (its arrangement moved with its drivers), SKY130's 8 %, the private kits' 8 to 13 %. Two edge pins found no landing on the lifted pins' 200 nm step, their window between the sense inverters' input routes narrower: an edge pin's points a quarter of that apart (`pins.EDGE_STEPS`), every point at one distance from the side kept (`_thinned`). The sense input loads its plate by the inverter's input capacitance (the mosfet table's `input_f_per_unit`: the charge an inverter at FO4 takes over its input's swing), which the drivers' sizing adds to the main plate's load. On a small stage both plates are tens of LSB each and their residues cancel only while they settle together: its difference driver the kit's least inverter, stronger than its plate asks, and its main plate now more loaded than the difference plate (the sense inverter's input and wiring), GF180's last stages settled post-layout in 0.64 ns; where the difference driver is drawn faster than the main, the main now settles its plate's own step too (`subckt._keys`; GF180's last stages 0.38 to 0.49 ns, its MSB 0.53 ns the slowest). Two post-layout fixes the new layouts called for: the difference band's landings in a kit whose shield is M1 stood a plain M1 space from the band's rail, where the rail, a wide metal, asks more, so the rails are shaved beside every M1 no row cell draws, ALIGN's and the MOM units' landings alike (`flow.layout.post.clear_rails`); and a rail's M2 bridge that runs into a shield on M2 filled the gap to it beside its bar alone, not beside its cuts' pads (SKY130's pads stood 0.1 um from its shield), now beside both (`post._rail_bridge`).
- Why the capacitive DAC goes by 2.5-D in TSMC65 (2026-11-09): FasterCap does not converge on any of its arrays (the smallest 10-bit array not within half an hour, its first pass unphysical; FRIDA-1's array fails, and so does one of its long strips alone), while it does on the comparator and the sampler, so neither a conductor count nor a fallback on failure separates them. On the DAC's own cells against FasterCap, the 2.5-D engine's error on a stage's weight is one common scale, which cancels in the ratios: the arrays' weights come within a fraction of an LSB at 10 to 14 bits and their gain within a few percent. It is loose on what a common scale does not cover: a top plate's load split between its shield and the substrate (a factor of two to three each way, their sum, which the gain sees, much closer), the coupling between neighbouring strips, and a plate's absolute value with the coefficients' source. It is a single-threaded Python loop, minutes to hours on an array against Calibre's seconds. Neither of Calibre's modes is the reference on the arrays: xRC's ratios are sound but it counts almost no field to the substrate; xACT's absolute values are close but noisy on the smallest stages at frida's accuracy setting.
- Against the kits' extractors (2026-10-27; 8 µm MOM test structures, a ring on two metals and a difference unit on three in each PDK, five structures in TSMC65, couplings above 0.05 fF): the plates' couplings, which a CDAC's weights are, agree to a median of -0.6 % (Tower180), -0.8 % (TPSC65), -2.3 % (TSMC28), +4.6 % (LF150) and -5.2 % (TSMC65, every plate between -6.1 and -4.6 %: a systematic offset of the stack, not noise); IHP130's 135 structures to -0.65 to -0.9 % (FasterCap's couplings below 0.3 fF move by up to 7 % with its tolerance, so neither extractor is the reference there). The shield's couplings agree within -8 to +11 % (TSMC28's one short structure +28 %), and the split of a net's ground most loosely (tens of percent): a kit's extractor counts an enclosed finger's field to the substrate where FasterCap ends it on the enclosing frame. TSMC28's difference unit did not finish (FasterCap's mesh outgrew 35 GB).
