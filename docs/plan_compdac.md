## Architecture and typed data contracts

### Native parameter hierarchies

Do not force all comparator or CDAC producers into one synthetic testbench parameter type:

- Physical chip measurements, generated-ADC SPICE, and whole-chip PEX use `AdcTbParams -> AdcParams -> CompParams/CdacParams`.
- Standalone comparator netlist simulations use `CompTbParams -> CompParams`.
- Standalone CDAC netlist simulations use `CdacTbParams -> CdacParams`.
- `MeasCompExt` and `MeasCompInt` continue to mean external versus internal observability, not physical versus simulated origin. `MeasCdacExt` and `MeasCdacInt` follow the same rule.
- Set `MeasCompExt.param` to `AdcTbParams`; allow `MeasCompInt.param` to be `CompTbParams | AdcTbParams`. Mirror this for CDAC with `MeasCdacExt.param = AdcTbParams` and `MeasCdacInt.param = CdacTbParams | AdcTbParams`.
- Keep the concrete runtime parameter class in HDF5 type metadata and reconstruct it on read. Add round-trip coverage for every accepted measurement/parameter pairing.

This leaves `flow.analysis.comp` digesting `MeasCompExt | MeasCompInt` as it does now. The analysis reads the common `CompDaq` fields and does not depend on whether the nested comparator parameters arrived through `AdcTbParams` or `CompTbParams`. Source-specific parameter extraction belongs in comparison and cohort-building helpers.

### Per-point measurement files

- One fixed input voltage, ADC selection, CDAC state, sampling mode, direction, and `dac_diffcaps` setting produces one HDF5 file containing all repeated trials for that point.
- The parameter object is the source of truth for programmed setpoints and static configuration. Repeat canonical `vin_diff_v` and `vin_cm_v` in DAQ rows so existing analyses can concatenate points without understanding the parameter hierarchy.
- Store actual instrument identities, voltage/current readbacks, timing/IDELAY settings, and calibration identifiers in `MeasInfo`. Scope records remain measured waveforms rather than parameter values.
- Extend `CompDaq` additively with optional `fastrx_word` and decoded `fastrx_frame`. Require them for new external physical measurements and leave them absent for internal simulations. Store only the scalar decision in `decision`; do not invent a 17-element comparator vector.
- Evolve the CDAC DAQ contract to represent both the before-update and after-update P/N states, `vin_cm_v`, `vin_diff_v`, comparator decision, and—externally—raw FastRX word/frame. Preserve old CDAC HDF5 readability by treating existing `dac_state_p/n` as the after-update state; old records without a before-state remain valid for their original waveform analyses but are ineligible for switching-weight extraction.
- A physical point is valid only if every expected FastRX word is present, identifier `0x1` is correct, frames are contiguous modulo the available frame bits, and unused partial-frame data bits are zero. Transport corruption aborts that point rather than being encoded as an analog comparator failure.

### Cross-source comparison

- Follow the existing ADC-level comparison pattern: form homogeneous physical, generated-ADC, PEX, and standalone cohorts; analyze each cohort independently; compare only typed analysis summaries in an explicit runner.
- Before comparison, check the relevant `CompParams` or `CdacParams`, supply, temperature, common mode, switching state, and measurement mode. Do not require irrelevant ADC wrapper fields for a standalone block result.
- Map a physical operating point to a simulation PVT corner only in the comparison runner and record that mapping in its output. Do not hide it in measurement construction or generic analysis.

## Comparator scan

### Campaign construction

- Build the initial campaign for ADC00–ADC03 from matching direct sweep fields on physical `AdcTbParams` and standalone `CompTbParams`. Do not introduce an intermediate parameter class which has no corresponding netlist boundary.
- Use the complete 0--25 mV differential grid at 100 uV spacing with 1,000 decisions per point. Comparator thresholds are expected inside this qualified interval, so comparator acquisition does not use the CDAC scan's adaptive coarse stage. A curve which does not reach both probability tails remains visibly unbracketed instead of causing the runner to chase a wider input range.
- Keep each fixed input in its own HDF5 file. The runner may reuse completed point files when resuming an interrupted campaign. Capture every 1,000-trial point as ten contiguous-frame 100-trial sequencer batches and concatenate them into that one point record. Run ordinary points without a host delay between batches. Once per curve, time-distribute the first transition-region checkpoint over the original 0.5 s batch interval. This retains all 1,000 decisions and an in-curve measurement of slow analog wander while removing repeated idle time from the remaining points.
- Main comparator characterization uses Vin_cm values 0.700 V through 1.200 V inclusive in 0.100 V steps. The offset-only target is the 0.800 V slice of this identical grid.
- Use the accepted differential-amplifier/AWG calibration for every point and refuse inputs outside its declared validity range. The explicitly qualified 1.200 V common-mode slice permits its positive input to reach 1.2125 V at the 25 mV endpoint.

### Main track-mode sequence

- Configure lab mode 2, encoded by the hardware `dac_mode=0` A/B-select bit; this disables comparator-driven one-hot SAR updates. Calculate the closest weighted 50% code independently for the selected radix with `_convert_dac_rail_percent_to_codes()`, and program it on both P and N sides for both A and B.
- During setup, begin with one SAMP-low serializer word so the latch-based sampling clock gates can capture a newly programmed `en_samp_*`, then leave SAMP high. Assert INIT and issue one LOGIC edge to load A, then return INIT and LOGIC low. RTL behavior guarantees that this edge loads A only; B is not applied until a later LOGIC edge while INIT is low.
- Hold both sampling switches continuously on. Do not pulse INIT, SAMP, or LOGIC during measured repetitions.
- For each repetition, issue exactly one COMP event and one `SEQ_CLK`-wide RX_SEN pulse positioned by the calculated capture timing.
- Decode the flushed partial FastRX word with decision in data bit 0. Validate and persist the raw 32-bit word and frame counter; require the remaining data bits to be zero.
- Generalize the existing capture-timing/IDELAY calculation to this one-sample window. Gate the first hardware campaign on a scope capture that verifies COMP, COMP_OUT, RX_SEN placement, and modeled setup/hold margin.

### Complementary-CDAC coupling diagnostic

- Run every curve at Vin_cm = 0.700 V. Request P-side weighted VDD_DAC coupling at 0%, 25%, 50%, 75%, and 100%; drive N with the complementary 100%, 75%, 50%, 25%, and 0% state.
- Implement `_convert_dac_rail_percent_to_codes()` as a pure private helper in `scan_cdac.py`. It accepts a target in the inclusive 0–100 percent range plus the selected ADC weights, minimizes absolute normalized-weight error, and returns every tied closest C16-to-C1 bit string in lexicographic order. Campaign construction uses the first returned code.
- Import that helper into the comparator sampling builder. Use bitwise-complementary P/N codes at 0/100, 25/75, 75/25, and 100/0; at 50/50 use the same helper-selected weighted midpoint on both sides.
- Program A equal to B independently on each side so this test changes the static P/N CDAC coupling without a LOGIC transition. For each of the five states, acquire matched track and hold S-curves. Track leaves SAMP high through comparison. Hold closes both sampling switches to acquire, reopens them, waits 20 ns, and then compares.
- Use the complete 0--25 mV differential grid at 100 uV spacing and 1,000 decisions per point for all ten curves per ADC. Treat these curves as a coupling and sampling-noise diagnostic; they do not provide an absolute capacitance estimate.
- The earlier 21-state diagnostic programmed identical P and N states, so it varied a common CDAC back-state rather than the requested differential coupling. Its maintained scan and analysis targets are removed. This does not affect the separate `cdac_ab` extraction scan or analysis.

### Comparator analysis and calibration output

- Aggregate decisions by input voltage sorted by `vin_diff_v`, then calculate P16, P50, and P84 by monotonic interpolation. Define offset as P50 and input-referred noise sigma as `(P84 - P16) / 2`.
- Correct the current monotonicity check so it operates in voltage order, not probability-sorted order. Use curve-wide Bonferroni-adjusted 95% Wilson intervals as the minimum uncertainty so a long fine grid does not almost certainly fail through repeated pairwise testing. For every physical point captured as explicit batches, widen that interval by the observed between-batch 95% interval so correlated trials are not treated as 1,000 independent Bernoulli decisions; a nonzero batch interval additionally exposes slow wander. Classify only reversals beyond this uncertainty envelope as non-monotonic.
- Keep analog validity out of `MeasCompExt`/`MeasCompInt`. A common-mode summary may classify a curve as valid, unbracketed, stuck-low, stuck-high, or non-monotonic. In isolation, a constant curve is only unbracketed; label it stuck only when the requested range and neighboring common-mode behavior support that conclusion.
- Plot every common-mode S-curve plus offset, noise, and validity versus common mode. For the complementary-CDAC campaign, plot all ten fitted CDFs with five Nord-blue track shades and five Nord-red hold shades, plus paired vertical Gaussian violins of threshold and input-referred noise versus requested P/N coupling.
- Do not let acquisition rewrite calibration YAML. After review, manually curate the accepted Vin_cm = 0.800 V offset/noise for each ADC under its board entry in `flow/scans/map_board.yaml`, including source HDF5 path and timestamp. CDAC campaign generation fails clearly if the selected ADC lacks this accepted comparator calibration.

## CDAC scan

### Campaign matrix and voltage planning

- For each of ADC00–ADC03, characterize all 16 elements on P and N, both 1-to-0 and 0-to-1 directions, with both `dac_diffcaps=0` and `dac_diffcaps=1`.
- Use Vin_cm = 0.800 V. Predict each transition from the selected radix weights and the flavor-specific PEX top-plate parasitic. The planning denominator is the complete main-plus-diff weight sum plus the fixed top-plate parasitic expressed in the same normalized units. Correct the center with the stored per-ADC comparator offset, then convert the desired differential input through the calibrated AWG/differential-amplifier model.
- After a final-sequence C16 commissioning run is accepted, manually curate one direction-averaged measured-to-PEX step scale per ADC and `dac_diffcaps` mode. Apply it only to center later adaptive sweeps (including the opposite side and smaller elements); keep the PEX weight ratios for relative planning, preserve symmetric rising/falling seeds about the comparator offset, and never use this planning scale in capacitance extraction.
- Retain a CDAC-specific adaptive coarse/fine acquisition policy: 1 mV and 128 trials until probability spans 0.10–0.90, followed by 100 uV and 1,000 trials across that bracket. Unlike comparator characterization, CDAC transition inputs span both polarities and hundreds of millivolts across element weights, sides, directions, and diffcap modes, so a universal fine grid would be wasteful.
- Apply the comparator scan's ten-batch fine-point acquisition and one transition-region drift checkpoint per curve to CDAC curves as well. Preserve one FastRX reset per HDF5 point so raw frame identifiers remain contiguous across all ten sequencer starts.
- Treat coarse points only as the bracket-finding prepass. When a completed fine stage exists, fit CDAC P50 and validity from its 1,000-trial points only; retain coarse/fine disagreement as diagnostic evidence rather than mixing acquisition epochs and trial counts into the extraction curve.
- Resume CDAC acquisition only at a completed whole-curve boundary. Persist one acquisition-session identifier in every point and mark only the final fine point complete; reject a directory containing any partial, mixed-session, or post-completion curve. Start a fresh run directory after interruption rather than combining analog points across bench reinitialization.
- Before any hardware command, calculate the P and N top-plate voltages both before and after the proposed transition. Reject the complete point if any predicted plate is below 0.400 V or above the configured VDD_A.

### State construction and repetition sequence

- Falling case: A is all ones on both sides; B differs only by clearing the selected bit on the selected side.
- Rising case: A is all zeros on both sides; B differs only by setting the selected bit on the selected side.
- Configure lab mode 2 (`dac_mode=0`, explicit A/B selection) and program the complete A/B P/N states. Verify the slow-register readback before acquisition.
- Before each point, issue the explicit A-state setup sequence and hold its final SAMP-high word for 10 ms so the new external voltage preconditions both selected top plates. Each measured repetition then performs this exact order: assert INIT and issue one LOGIC edge to load A; deassert INIT; close both sampling switches for 17 sequencer words (85 ns at 1.6 GBd); reopen both sampling switches; issue one LOGIC edge with INIT low to load B; wait the parameterized CDAC settling interval; issue one COMP event; issue one-clock RX_SEN; validate and record the partial FastRX word.
- Keep the Basil operations and safety-relevant order visible at the scan call site. Pure state generation, predicted-voltage checks, decoding, and analysis may be helpers.
- Scope-commission one representative transition in each direction and each `dac_diffcaps` mode before the full matrix. Verify A load, sampling aperture, B update, settling delay, comparator event, and returned decision. Full decision campaigns do not download redundant scope traces; commissioning mode captures at most one trace per curve. A decision-only `MeasCompExt` or `MeasCdacExt` stores `wave=None` through an explicit backward-compatible HDF5 marker.

### CDAC analysis

- Fit P50 only; do not interpret P16/P84 as capacitor noise for v1. Invalid or unbracketed curves remain analysis outcomes, not measurement types.
- Convert each comparator-corrected P50 into a signed normalized CDAC step. Average opposite directions for the element weight and retain their half-difference as switching-direction bias. Compare P and N results for side asymmetry.
- For each element and side, let `w_plus` be the direction-averaged normalized magnitude measured with `dac_diffcaps=1`, and `w_minus` the magnitude measured with `dac_diffcaps=0`. Report `Cmain/Ctotal_top = (w_plus + w_minus)/2`, `Cdiff/Ctotal_top = (w_plus - w_minus)/2`, and the effective main-minus-diff weight `w_minus`.
- Produce per-ADC plots of all 16 normalized weights, residual from ideal/PEX expectation, P/N asymmetry, direction bias, and `dac_diffcaps` separation. Also produce an ADC00–ADC03 comparison summary.
- Do not report absolute femtofarads in v1. Controlled kT/C and impedance experiments remain follow-up work because the current track/hold difference is confounded by CDAC-rail coupling.

## Implementation order and verification gates

1. **Typed contracts and compatibility:** update parameter annotations, DAQ fields, validators, HDF5 round trips, and source-specific parameter extractors. Confirm existing ADC and legacy comparator/CDAC tests still pass.
2. **Pure builders and decoders:** implement sweep scheduling, comparator/CDAC state construction, plate-safety calculation, `_convert_dac_rail_percent_to_codes()`, and one-bit partial-FastRX decoding. Add exhaustive or parameterized unit tests before instrument code.
3. **Comparator acquisition:** implement explicit instrument setup/shutdown, balanced-state loading, track/hold sequences, per-point HDF5 output, resume behavior, and scope commissioning mode.
4. **Comparator analysis and runner:** implement corrected S-curve analysis, common-mode and rail summaries, plots, homogeneous source cohorts, and ADC-style cross-source comparison checks. Curate the first accepted comparator calibrations manually.
5. **CDAC acquisition:** implement the full state matrix, safety rejection, calibrated sweep centering, exact A/sample/B/compare sequence, partial capture, and per-point persistence.
6. **CDAC analysis and runner:** implement P50-based normalized extraction, direction/P-N/diffcap decomposition, plots, and cross-source summary comparison.
7. **Hardware rollout:** pass a one-ADC/one-cap smoke test, then all four modes for one cap, then all 16 caps on ADC00, then ADC00–ADC03. Expand to all 16 ADCs only after these stages complete without transport, safety, or sequencing failures.
