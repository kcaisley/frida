# The block pipeline

A building block runs as one pipeline: its design parameters make a circuit, testbench runs of it are simulated, each run's raw output is read as a measurement, analyses turn measurements into results, and the results become the block's metrics, its figures and the record of one instance of its design space. Each step is a file of the block's folder, and the names in each file are the same in every block, so `comp.Params`, `comp.netlist` and `comp.analyze_offset_noise` are read by their namespace. A block contributes data and stage functions only; the CLI (`python -m flow`) is the one entry point. The comparator (`flow/comp`) is the first block on it, the sampling switch (`flow/samp`) the second, the capacitive DAC (`flow/capdac`) the third and the ADC (`flow/adc`), assembled from them, the fourth; the others follow one by one (`MIGRATED` in [`flow/test_pipeline.py`](../flow/test_pipeline.py)).

## Stages

Each stage imports only the stages above it in this table.

| File | Gives | What |
| --- | --- | --- |
| `params.py` | `Params`, `TbParams`, enums, constants (`valid(params, pdk=None)` in a block not yet typed so; `layout_view(params) -> Params`, the design as its layout draws it, where that differs: the comparator's output stage the PDK's library cells) | The design (an hdl21 paramclass, registered as a `flow.pipeline.Params`) and one testbench run of it (a frozen dataclass deriving `flow.pipeline.TbParams`: at least its `pdk` and its design, `params`); the run's schedule (which input each decision sees) is a property of `TbParams`. Its fields are typed so that every design the class admits builds (choices as enumerations, sizes `PositiveInt`): an invalid one is refused when it is made. Its defaults are a reference design. What a grid or a search varies is not declared here but in a space of it (`sweep.py`, `opt.py`). |
| `subckt.py` | `Nets`, `netlist(params) -> h.Module` | The circuit: its nets, the generator. |
| `sim.py` | `testbench(tb) -> h.Module`, `simulate(tb, run_dir) -> Path`, `read(raw, tb) -> Meas` (optional) | The testbench of one run, and its simulation, which leaves the raw output on disk and parses nothing (it may leave beside it what reading it needs, the names of the signals it saved). Which signals are saved is declared here, from `Nets`. A block whose raw output is not what `flow.pipeline.read` reads (the converter's rows of conversions, decoded from its waves or written by its behavioral engine) reads it itself (`read`), which the runner and the optimizer call in place of the shared one. |
| `types.py` | `Analysis<Thing>`, `Metrics` | The block's results: frozen dataclasses deriving `flow.pipeline.Analysis`, data only; and its metrics, a frozen dataclass deriving `flow.pipeline.Metrics`, each field declared with `flow.pipeline.metric` and which way is better (`lower`, `higher`, `true` for a flag that must hold, `none` for a number only reported). |
| `analysis.py` | `@analysis analyze_<thing>(meas, *, prior) -> Analysis<Thing>`, `metrics(...) -> Metrics` | One measurement (or a sequence) in, prior results by keyword (one it does without where that was not measured optional: `prior: AnalysisX \| None = None`), one result out; an analysis may group its input and apply the block's other analyses to each group. `metrics` gives the record's numbers (a block not yet typed: `dict[str, float]`), None where the runs of a level did not measure one. |
| `plots.py` | `@plot plot_<thing>(result) -> Plot` | Each figure as a `flow.pipeline.Plot` spec, from results alone. |
| `sweep.py` | `@grid` and `@named` functions, `runs(pdk, params, level=Level.FULL) -> dict[str, TbParams]`, `record(measurements) -> Record` | The design space, the runs that characterize one instance at a level (`flow.pipeline.Level`: `SCREEN` the quick ones, `SEARCH` what an optimization needs, `FULL` all, `CIRCUIT` all and the circuit simulator's runs of a block whose full characterization is behavioral, `FULL`'s runs elsewhere; each including the levels below), and its record from the runs of any level (which also names the runs whose waveforms the viewer shows); a design that fails is recorded so, not raised. Nothing else: no module constants. |
| `model.py` | `Model` | The behavioral model: one instance's characterization (its record, looked up by `flow.sweep.lookup`) as the stand-in a higher level of the hierarchy simulates (the ADC's behavioral model). |
| `opt.py` (optional) | `@problem` functions | What an optimization of the block minimizes and must meet (`flow.pipeline.Problem`): costs and bounds by metric name, and the space it searches (`space`: a `widen`ed `Params`); a function of a few knobs, `adc(bits=12)`, given the PDK (a `flow.pipeline.Pdk`) where it takes one. A block sized by its sweep alone has none. |
| `layout.py` (optional) | `lay_out(params, pdk, run_dir) -> Path` | The block's own layout flow, for a block assembled from laid-out blocks (the ADC; later the SAR logic): OpenROAD places and routes one instance into `run_dir` and gives its GDS, which the layout verbs run in place of ALIGN's (`flow.layout.step.lay_out_one`). Its signoff is the one it states: its own, where it signed the layout off itself (`run_dir/signoff_summary.json`, `flow.layout.signoff.run_signoff`'s), recorded as it is; else the shared signoff (`flow.layout.signoff`) against the LVS source it wrote (`run_dir/source.cdl`), extracted as the shared step's are; else DRC alone (blocks side by side, unconnected). A block has it or states its ALIGN placement in `subckt.py`, not both. |

An analysis and a figure declare their stage with `flow.pipeline`'s `@analysis` and `@plot`: each checks its function when the module is imported (one measurement or result in, earlier results by keyword, each a result or, optional, `X | None = None`, an `Analysis` out; results in, a `Plot` out), so a block that breaks the contract does not import, and their types let ty reject an analysis that returns anything but an `Analysis`. Module constants live in `params.py` (the design's and the testbench's) and `sim.py` (what a run saves) alone. `types.py`, `analysis.py` and `plots.py` do no file I/O: a private helper there (`_name`) is a pure function too.

A block states its layout in one of two ways at most, never both. A block of devices states it in its generator: `netlist` places its instances as it makes them (`flow.layout.hdl21align.place`: rows of the module's own instances, top first, complete or left to ALIGN by name of instance; a child module its own subcircuit, placed by its own `place`), and one shared step lays out any such block (`flow/layout/step.py`: its module compiled once, its ALIGN and LVS netlists from hdl21 and vlsir, a constraint file a module, ALIGN and the signoff; the sweep's layout step and `python -m flow layout`); a generator that states nothing is placed by ALIGN alone. A block assembled from laid-out blocks (the ADC; later the SAR logic) has its own flow instead, `layout.py`, in place of the shared step: the layout verbs run its `lay_out` and sign it off as it states (the table above; the contract refuses a `layout.py` beside a `subckt.py` that calls `place`). `flow.sweep.lookup.laid_out(block, pdk, params)` gives an instance's newest layout entry, from a layout run or a sweep run's record, by its digest, as `characterized` gives its record. `params.layout_view` where a block's layout draws another view of it. A block's folder holds these eight files, `opt.py` where it is optimized and `layout.py` where it lays itself out, and nothing else but its package's `__init__.py`, its `readme.md` and a `test_<file>.py` for a file (the contract refuses any other: no `targets.py`, no helpers). `model.py`, `opt.py` and `layout.py` sit above `sweep.py`, side by side: none imports another, and no stage imports them.

A space is a design with some of its parameters widened, written by attribute on a space typed as the block's `Params` (so an editor completes the names): `space = widen(Params())`, then `space.latch = every(Latch)`, `space.diffpair_w = steps(32, 512, n=3, log=True)`, `space.preamp_c_ff = steps(30, 120, n=2, log=True, when=Bias.DYNAMIC)` (a range that applies only where the design holds that member), and a bare value holds a parameter (`space.input_pair = MosType.NMOS`); every parameter not set is held at the base's value. Each is checked as it is set: a name the class lacks, or a value it refuses, raises then. One notation serves both searches: a grid takes `steps`' `n` points and each of `values`, every combination of them; a search (`opt.py`) any value in a range and any of the values. `@grid` makes a function returning a space, or a list of them (their union), the block's grid; it may take the PDK (a `Pdk`) for per-PDK ranges, or `@grid(pdks=(Pdk.TSMC65, ...))` keeps it to those, and its instances are labelled by what varies, `topologies(latch=STRONGARM, bias=SWITCHED, diffpair_w=128)`. Values may carry names, `values({"frida1": comp.FRIDA1, "quiet": ...})`: a grid labels a point by the name, not by the value (a comparator inside a converter would label as its whole repr), and a search offers the names. A grid may return its spaces by name, a mapping: a point is labelled by its space's name as well, `arrays(binary)`, or `arrays(binary, bits=12, scale=1, weight_impl=UNIT_CAPS)` where that space varies, and `Grid.spaces(pdk)` gives the spaces by name, so a caller takes one by its name: `capdac.arrays.spaces(pdk)["binary"].base`. `@named` gives one fixed instance a name (`@named(swept=False)`: named, for a layout, but not swept). The runner expands them all, and, in a block with a `params.valid`, keeps in each PDK what it admits. An instance is its parameters: its digest is its identity, its label (`dynamic_bias(ratio=3.5, k=3)`) only a name.

Between `sim.py` and `analysis.py` sits one function every block shares (unless its `sim.py` reads its raw output itself, `read`), `flow.pipeline.read(raw, tb) -> Meas`: every saved signal on the simulator's time axis (`time_s`, voltages `v`, supply currents `i` by net name), the run's `TbParams` and identity. A Monte Carlo of operating points (Spectre's `montecarlo` with `savefamilyplots=yes`: a plot `mc-<run>_<analysis>` a run) reads as one measurement whose signals hold a value a run, in order (`time_s` empty, `readbacks["runs"]` their count; hdl21's `MonteCarlo` takes the statement's `options`). Readback never resamples; an analysis that needs uniform samples makes them itself. How finely the simulator writes its output is the run's (`TbParams`): the comparator's runs strobe it every 2 ps, as on the simulator's own steps its delays and energy came out wrong, the sampler's every 5 ps. The raw file is removed once read; the measurements of the runs whose waveforms the record names are kept as HDF5 (`result.h5`, `flow.analysis.io.write_measurement`), which the viewer and `plot --from` read.

A lab capture meets a simulation in a result, not a measurement: the comparator's bench scans write `comp.AnalysisDecisions` (each trial's input and decision), which `comp.analyze_decisions` gives for a simulation, and the offset, noise, S-curve and common-mode analyses take those. A quantity both measure is one spec, in its SI unit, so a capture and an instance overlay in Compare: the comparator's noise and offset over the common mode (`noise_cm`, `offset_cm`, of `comp.analyze_common_mode`) are a record's and a campaign's alike. A block's analyses also read a higher block's captures where those observe it, once the higher block gives them in the block's own terms, as a CDAC's switching curves become the comparator's decisions (`capdac.analyze_decisions`): a converter's capture as its comparator sees it (`comp.AnalysisConversions`, from `adc.analyze_conversions`), which `comp.analyze_scope_edges` (the bench's scope records of its output) and `comp.analyze_edge_eye` and `comp.analyze_response` (a simulation's latches) take; a point of a CDAC stage's switching curve as the CDAC sees it (`capdac.AnalysisSwitching`, from `adc.analyze_switching`), which `capdac.analyze_transition` and `capdac.analyze_cap_mismatch` take. A block never imports the higher block's measurement type: the measurement module reaches the higher block, which imports the block's package, a circle import-linter refuses.

## Running a block

```sh
python -m flow run <block> [--pdk P ...] [--instance I ...] [--missing] [--level L] [--workers N]
python -m flow layout <block> [--pdk P ...] [--instance I ... [--auto]] [--no-pex] [--workers N]
python -m flow table <block> [--workers N]
python -m flow plot <block> [FIGURE ...] --from DIR [--from DIR ...] [--backend matplotlib|web] [--priors]
python -m flow opt <block> --problem P [--pdk P] [--budget N] [--workers N] [--best N]
```

`run` characterizes the design space (or the instances picked: a name, a label or a digest) into a fresh `build/<block>/<run>`, at a level (`--level screen|search|full|circuit`, `full` by default; `circuit` only for picked instances); the sweep runner (`flow.sweep.runner`) simulates each of an instance's `runs`, reads each and hands the measurements to `record`, and its record keeps the level it ran at. `--missing` characterizes, into the newest run, its instances that failed, never ran or ran below the level asked for, so adding the circuit simulator's runs of a few instances leaves the rest of the run as it is. `layout` lays out the newest run's instances, or named instances, by ALIGN (or a block's own `lay_out`), signs each off (DRC, LVS) and extracts it (KLayout-PEX with FasterCap: every net's capacitances, minutes a block; not with `--no-pex`). `table` exports the viewer's tables. `plot` draws a sweep run's records' figures, or the figures of captures (a run of a lab campaign: its directory, each HDF5 file beneath, or files), a block's lab studies: each `plot_<thing>` (its own, or of a block whose results its analyses give) whose result its captures make as the block's analyses chain them, for each board and channel (`flow.plot.figures`): a capture of the result's kind, or the analysis that gives it, whose input is made the same way, a capture each (a figure each) or all of its kind; a sequence made one capture at a time taken one sweep at a time where the captures name their sweep (`MeasAdc.sweep`: one curve a sweep over the rate); its required priors made the same way from its own input, its optional ones left out (with `--priors`, each its captures give: a ramp decoded by each calibration); a result several analyses give (each of its kinds) drawn for each, and an analysis of the results a channel makes once (operating conditions, as a sequence map) for each channel and for a board's channels together. An analysis that raises (`ValueError`, or a `KeyError` for a wave a capture lacks) is not of those captures: said, not drawn. An analysis of a simulation's plain waves (`pipeline.Meas`) takes captures of exactly that type, never a block's own measurement (a lab capture, `MeasAdc`). A block not on the pipeline keeps `python -m flow <block>.<target>` until it moves; the CLI takes a verb as its first word, a target otherwise.

## Figures

`plots.py` returns specs only. The viewer draws a record's from their JSON with Plotly; `flow.plot.render(plot, path)` draws any with matplotlib in the analysis plots' style.

A spec (`flow.pipeline.Plot`) holds curves over x (series, or a family of counted paths), a map over x and y (`Heatmap`: a value in each cell, its cells' edges as `calc.histogram2D` gives them, by decade where it asks), categories on either axis (`x_labels`, `y_labels`: a map's columns or rows, a sequence or a rate, each ticked by its name), labelled lines at values of x or y (`Marker` in `x_markers` and `y_markers`: a bandwidth, Nyquist, a tone; a floor, a limit) and labelled ranges of x shaded behind the curves (`Band` in `x_bands`: a line's bins, a decade). Both renderers draw each alike: a few points marked and a long series (over 100 points) a plain line, the map in the density colours beside its colour bar, the markers dashed and the bands shaded in the spine's grey, each labelled inside the plot at its edge, and a log axis ticked by the same rules (linear steps within a decade, 1, 2 and 5 of each decade to 2.5 decades, the decades beyond, plainly from 0.001 to 10000). What a figure needs beyond these is added to `Plot` and to both renderers once, never drawn for one figure alone. A record keeps a spec as its JSON (`Plot.to_json`, read back by `Plot.from_json`), its y categories, markers, bands and map only where it has any.

## Checks

Pre-commit and CI hold a migrated block to this. A migrated block is every block with a `sweep.py`, a new one too, unless `NOT_MIGRATED` in `flow/test_pipeline.py` names it (that list only shrinks), and no check names a block: each finds the migrated ones itself. A block without a sweep is outside them until it has one: the sequencer (`flow/seqgen`) has, for now, its types, analyses and plots alone (the serializer's eyes, the scope's decode against FastRX's), which the scans import directly.

- [`flow/test_pipeline.py`](../flow/test_pipeline.py): the stage files, the public names each defines, their signatures (an analysis's optional prior as `X | None = None`), no nested functions, in `types.py`, `analysis.py` and `plots.py` no file I/O (in their private helpers either), `sweep.py` only grids, named instances, `runs` and `record`, no `targets.py`, a `layout.py` (its `lay_out` alone) only beside a `subckt.py` that calls no `place`, and no run and no path under `build/` named in the block's code. Its known-violations list only shrinks.
- import-linter (`[tool.importlinter]` in `pyproject.toml`): one contract orders every migrated block's stages (`model.py` at its top, `opt.py` and `layout.py` optional beside it, none importing another; `flow/test_pipeline.py` holds its containers to the migrated blocks), and `flow.pipeline` imports no block.
- Ruff ICN003: outside the block, `from flow import comp` and `comp.Params`, never `from flow.comp import Params`; inside it the stages import each other relatively.
- ty on the base module and every migrated block's stage files, `opt.py` and `layout.py` (`typed()` in `flow/test_pipeline.py` lists them for CI).
- [`flow/netlist_hashes.py`](../flow/netlist_hashes.py): every instance's netlist as a hash (its structure before any PDK compile and, in each installed PDK, after it), recorded and compared by hand while the netlists still change (`uv run python -m flow.netlist_hashes record|compare <block>`, records in `build/netlists/`); not a test.
- A block with an `opt.py` (`flow/test_pipeline.py`): each problem searches a space of the block's `Params`, in which every combination of the choices builds and a range that does not apply (`when`) leaves the circuit unchanged; its metrics are typed, and its problems name metrics and bound only those with a direction.

## Optimizing a block

`python -m flow opt` is to a problem's space what `run` is to the grids (`flow.opt.runner`): one problem of the block in one PDK is a study (Optuna's TPE sampler, `build/opt/<block>/<pdk>/<problem>.db`), asked asynchronously across a process pool, so a slow design holds no other. A design is evaluated once by its compiled netlist's hash (`build/opt/<block>/<pdk>/evals/<hash>/`), shared by every problem of the block and rescored when a new study starts: the screen's runs, its layout by its structure's hand-written floorplan where the problem bounds area (a design whose gates alone exceed the bound is out before simulating), then the search's runs if no bound is broken yet. The objective is the problem's cost (`pipeline.objective`: the product of its cost metrics, each to its weight, a saturating factor where a cost has a scale, in their units: a comparator's J um^2), each bound's violation a named constraint (`pipeline.violations`); a design that misses a bound completes infeasible, its cost infinite, and only a broken evaluation fails.
